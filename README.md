# watchstats

视频观看覆盖统计库（Go，进程内内存，单线程调用）。营销侧用于回答"观众真正看过多少内容"，而不是进度条最远到过哪里：按内容覆盖去重，支持拖动、重复观看、多会话重叠与迟到事件引起的统计修正。

## 设计

- 每个 `Tracker` 对应一个固定时长的视频（≤ 7200000 ms）。
- 会话内事件按 `(TimeMs, EventID)` 升序维护在有序切片中；事件标识在会话内去重，重复投递直接忽略。
- 相邻事件对中，仅前一项 `Playing` 时贡献区间 `[PosMs, PosMs+min(时间差, 视频剩余))`，起点计入、终点不计入；最后一项无后继不贡献。
- 新事件插入时间线时，只撤回被拆开的相邻区间、再添加新产生的两个相邻区间，迟到事件引起的覆盖撤回由此增量完成。
- 每个观众用一个带引用计数的区间并集结构（`coverage`）合并全部会话的区间：同段内容无论重复播放几次、被几个会话覆盖都只计一次；撤回即计数减一。
- 视频汇总（有效观众数、平均观看比例、25%/50%/75%/100% 里程碑人数）随每次接收增量维护，接收返回后查询即为最新结果。

## API

```go
tr, err := watchstats.NewTracker(100000) // 视频时长（毫秒）
tr.Ingest(watchstats.Event{
    ViewerID: "u1", SessionID: "s1", EventID: "e1",
    TimeMs: 0, PosMs: 0, Playing: true,
})
watched := tr.WatchedMs("u1") // 已看时长（毫秒）
sum := tr.Summary()           // Viewers / AvgRatio / Milestone25..100
```

## 运行测试

```sh
go test ./...          # 全部测试（含性能测试）
go test -run TestPerformance -v .   # 只看性能测试输出
```

测试覆盖：

- `tracker_test.go`：验收场景（100 秒视频先播放到头覆盖 100 秒，补入 10 秒处跳到 90 秒继续播放的事件后覆盖降为 20 秒、四档里程碑归零）、多会话重叠去重、重复投递、拖动跳过、末尾截断、阈值等号、时长校验。
- `random_test.go`：乱序随机事件（含重复投递），每次接收后与从完整事件独立重算的结果比对。
- `perf_test.go`：20 万条事件、1 万名观众（一人 10 万条），再补 1 万条插入既有时间线中间的事件并逐条查询。本机实测补入阶段约 1 秒（预算 10 秒），堆内存约 40 MiB（预算 512 MiB）。
